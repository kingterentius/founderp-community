# The operating model

*How STREAM, Live / Give / Save, and PFOCUSR become a working system.*

## Three tags on every hour

Every block of time carries three tags. They answer different questions, so they don't compete.

| Tag | Question it answers | Lifespan |
|---|---|---|
| **Role** | Which pillar or brand consumed this time? | Stable — the STREAM question |
| **Project** | Which deliverable moved forward? | Ends when the project ships |
| **Value class** | Was this time worth having? | Stable |

### Value classes
| Class | Meaning |
|---|---|
| Revenue Now | Brings in money this month |
| Revenue Later | Builds future income |
| Leverage | Makes everything else faster or cheaper |
| Obligation | Must be done — compliance, commitments |
| Identity | Builds who you are and what you stand for |

**Saturday reads roles** (where did the hours go?). **Sunday reads projects** (what moves this week?).

## Portfolio rules

- **Work in progress is limited.** No more than three projects in progress at once, and no more than one per brand.
- **One ranked backlog** across everything you run.
- **Two-week cycles.** Plan on alternate Sundays with a written goal and three to five committed items, each with a definition of done. Review on alternate Saturdays.

## The system of record

FoundERP keeps all of this in one place — calendar for time, an ERP for projects, contacts, and money — so the weekly review reads from real data instead of memory. See [`/odoo`](../odoo/) for the setup pattern.
